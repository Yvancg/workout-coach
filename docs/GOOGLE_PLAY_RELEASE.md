# Google Play release setup

Workout Coach Android package:

- application ID: `com.yvan.workoutcoach`
- first release: `1.0.0`
- first version code: `1`
- minimum SDK: 24
- compile/target SDK: 36
- Android backups: disabled
- cleartext traffic: disabled
- Android permissions: Internet only

The package ID must never change after the first Play Console app is created.

## Release model

Use Google Play App Signing. Google should hold the app-signing key. Keep a separate upload key for signing each AAB before it is sent to Play.

Normal CI uses a disposable key generated during each run. That artifact is validation-only and must never be uploaded to Google Play.

The manual `Android Play Release` workflow uses the permanent upload key stored as GitHub Actions secrets.

## One-time upload key

Generate and securely archive an upload keystore outside the repository:

```bash
keytool -genkeypair -v \
  -keystore workout-coach-upload.jks \
  -alias workout-coach-upload \
  -keyalg RSA \
  -keysize 4096 \
  -validity 10000
```

Use a strong unique keystore password and key password. Keep at least one secure backup of the JKS outside GitHub.

Export the public certificate if needed:

```bash
keytool -exportcert -rfc \
  -keystore workout-coach-upload.jks \
  -alias workout-coach-upload \
  -file workout-coach-upload-certificate.pem
```

Encode the keystore for GitHub Actions:

```bash
base64 < workout-coach-upload.jks | tr -d '\n'
```

## GitHub Actions secrets

Configure these repository secrets before running the Play release workflow:

- `ANDROID_UPLOAD_KEYSTORE_BASE64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`
- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY`
- `VITE_SYNC_API_URL`

For API upload to internal testing also configure:

- `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON`

Do not store any signing private key, keystore password, or Google service-account credential in git.

## First Play Console setup

1. Create the app in Play Console using package `com.yvan.workoutcoach`.
2. Opt in to Play App Signing and let Google manage the app-signing key.
3. Register the upload certificate generated by the release workflow/keystore.
4. Create/configure the internal-testing track and testers.
5. If automated internal uploads are wanted, create a Google Cloud service account, enable the Google Play Android Developer API, link the service account in Play Console, and grant only the release permissions it needs.
6. Add the service-account JSON as `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON`.
7. Run the `Android Play Release` workflow with `publish_internal=false` first. Download and inspect the signed AAB and upload certificate.
8. After Play Console declarations are complete, run again with a new version code and `publish_internal=true` to publish to internal testing.

The uploader uses the Android Publisher API internal-test track identifier `qa`. It creates an edit, uploads the AAB, assigns the uploaded version code to internal testing, and commits the edit.

## Version rules

- `versionCode` must be a positive integer and must increase for every Google Play upload.
- `versionName` uses semantic versioning, for example `1.0.0`, `1.0.1`, `1.1.0`.
- GitHub workflow inputs override the Gradle defaults at release time.
- The default repository version remains `1.0.0 / 1` until the first Play upload is accepted.

## Play policy gates before submission

These are not Android build issues and must be completed in Play Console / the public product:

- Public privacy policy URL, also linked or shown inside the app.
- Data safety form describing authentication and synced workout data.
- Health apps declaration. Workout Coach fits **Health and fitness > Activity and Fitness** because it records exercise routines/workouts.
- Account deletion: because users can create/login to an account, provide both an in-app deletion-request path and an external web deletion-request URL, and delete associated account data when processed.
- Content rating.
- Store listing: app icon, feature graphic, screenshots, short/full descriptions and support contact.
- Internal-test reviewer access as needed.

Do not publish to production until these policy items and real-device authentication/sync testing are complete.

## Release verification

Before any Play upload:

```bash
npm ci
npm audit --omit=dev --audit-level=high
npm test
npm run lint
npm run check:android-release
npm run build
npx cap sync android
```

The release workflow additionally verifies the upload keystore and verifies the AAB signature with `jarsigner`.
